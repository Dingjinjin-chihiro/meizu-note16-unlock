## 三、进入 BROM（深刷）模式

1. **拔掉 USB 线**
2. 长按电源 **10 秒** 彻底关机（屏幕全黑、无震动）
3. 按住 **音量下 + 电源** 约 3 秒
4. **保持按住** 插 USB 线，插好后再松手

成功标志：手机屏幕全程黑屏，电脑识别出 `SPRD U2S Diag (COMx)`。
驱动：`sprd vcom 4.21.32.134`（已安装）。

> 注意：BROM 端口存活时间很短（几秒），必须"先挂监听再插线"。
> 脚本 `_dump/brom_write.ps1`、`_dump/unlock_step.ps1` 已内置自动捕捉与重试。

## 四、常用恢复操作

进入 BROM 后，在工作目录 `ums9621_Meizu_Note16` 下执行（POWER 为本机 BROM 漏洞地址 `0x65017f08`）：

### 还原原厂 init_boot（去掉 Root）

```
.\spd_dump.exe --wait 120 --reconnect exec_addr2 0x65017f08 ^
  fdl fdl1-dl.bin 0x65000800 ^
  fdl fdl2-dl.bin 0xbefffe00 ^
  exec w init_boot_a ..\_backup\init_boot_a.bin reset
```

### 还原原厂 uboot

```
.\spd_dump.exe --wait 120 --reconnect exec_addr2 0x65017f08 ^
  fdl fdl1-dl.bin 0x65000800 ^
  fdl fdl2-dl.bin 0xbefffe00 ^
  exec w uboot_a ..\_backup\uboot_a.bin reset
```

### 还原原厂 splloader

```
.\spd_dump.exe --wait 120 --reconnect exec_addr2 0x65017f08 ^
  fdl fdl1-dl.bin 0x65000800 ^
  fdl fdl2-dl.bin 0xbefffe00 ^
  exec w splloader ..\_backup\splloader.bin reset
```

### 查看分区表 / 读任意分区

```
.\spd_dump.exe --wait 120 --reconnect exec_addr2 0x65017f08 ^
  fdl fdl1-dl.bin 0x65000800 ^
  fdl fdl2-dl.bin 0xbefffe00 ^
  exec p reset
```

### 恢复 super 分区（fastbootd，一键脚本）

`super` 里装着 system/vendor/product 等所有逻辑分区。刷了 GSI 或把系统改坏之后，
用 `scripts/restore-super.ps1` 从 `_backup\super.bin` 一键写回，**不需要 BROM、不清数据**：

```powershell
# 设备在系统里 / recovery / bootloader / fastbootd 都可以，脚本会自己找路进去
.\scripts\restore-super.ps1 -Backup D:\_backup
```

脚本做的事：

1. 自动识别设备当前模式，必要时 `adb reboot fastboot` / `fastboot reboot fastboot` 进入 fastbootd
2. 校验 `partition-size:super` 与备份大小一致（10 GiB）
3. 还原 `vbmeta_a`、`vbmeta_system_a`（可加 `-SkipVbmeta` 跳过）
4. 按 1200 MB 分片写回，**失败自动缩窗重试**
5. 写完重启并等待系统上线

常用参数：

| 参数 | 用途 |
|---|---|
| `-DryRun` | 只检查环境、生成首片、不刷写 |
| `-From <字节>` | 从断点续写（脚本失败时会打印建议的偏移） |
| `-WindowMB 720` | 手动指定每片大小（默认 1200） |
| `-SkipVbmeta` | 不动 vbmeta |

> **为什么不能直接 `fastboot flash super super.bin`**：
> fastbootd 单次写入会话约 **70 秒**就返回 `Invalid argument`，
> 而 10 GiB 按 31 MB/s 需要 340 秒。脚本用 Android sparse 的 `DONT_CARE`
> 块跳过已写区间，每次只搬一段，从而绕开这个限制。
> 详见 [GSI尝试记录](GSI尝试记录.md)。

## 五、这次解锁的关键结论（踩过的坑）

1. **fastboot 公钥签名解锁在本机无效**
   `sign.pem` 的 4096 位模数在 `uboot_a.bin` 里根本不存在（已逐字节比对），
   `flashing unlock_bootloader` 必然返回 `Unlock bootloader fail.`。

2. **只刷 cboot 会黑屏**
   `fdl2-cboot.bin` 是别家签名的 u-boot，原厂 SPL 校验不过 → 卡死。

3. **必须先 `e splloader` 擦掉一级引导**
   这是整套流程的核心。擦除后：
   - 手机每次重启都会自动落回 BROM，全程不用再按组合键
   - 载荷写入的解锁标记不会被原厂 SPL 的重新引导覆盖
   之前失败就是因为没做这步，`miscdata` 一直是 64 字节全零。

4. **`spl-unlock.bin` 要自己生成**
   `gen_spl-unlock.exe splloader.bin <offset>`，offset 用第一次运行打印的值
   （本机为 `0x10f28`）。

5. **fastboot 大块写入不稳（`Too many links`）**
   8MB 的 `init_boot` 走 fastboot 两次都失败，改走 BROM `spd_dump w init_boot_a` 一次成功。
   以后刷大分区优先用 BROM。

6. **`e userdata` 的实际行为**
   `spd_dump` 会写 `misc-wipe.bin` 到 `misc` 并擦 `persist`（本机 `persist` 已被擦过一次，
   备份中有原文件，需要时可写回）。

## 六、注意事项

- 解锁后 **OTA 升级会失败或需要手动处理**，升级前建议先取消 Root
- 保修状态改变；开机有橙灯/警告提示属正常
- KernelSU 隐藏：在"设置"里给需要的 App 授权，或开启 "Umem" 相关选项应对检测
- 恢复出厂 / 刷官方包前，先确认 `splloader` 与 `uboot_a` 是原厂版本
- **不要删除本备份目录**，BROM 能救砖的前提就是这些镜像
