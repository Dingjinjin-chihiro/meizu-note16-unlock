`Play Integrity Fix`、`Device Faker`、`Tricky Store` 三者都在改写设备标识 / 完整性相关属性，
同时启用会互相覆盖，**反而导致检测失败**。保留 `Tricky Store + Zygisk Assistant` 一组即可。

恢复方法：

```powershell

adb shell su -c "rm /data/adb/modules/device_faker/disable"
# 重启生效
```

## 二、重要发现：`ro.boot.flash.locked` 是被伪装的

装上 PIF / Zygisk Assistant 后读取到：

```
getprop ro.boot.flash.locked        = 1        ← 假象
getprop ro.boot.verifiedbootstate   = green    ← 假象
getprop ro.boot.vbmeta.device_state = locked   ← 假象
```

但真实状态在 `/proc/cmdline`：

```
bl.lock=2        ← SPRD 的字段，2 表示解锁
```

**这是模块的正常行为**（为了让 App 以为设备未解锁）。
`grep -rl "flash.locked" /data/adb/modules/` 可以直接看到是
`playintegrityfix/service.sh` 和 `zygisk-assistant/service.sh` 在改写。

> 以后判断 BL 真实状态，不要看 `getprop`，要么看 `/proc/cmdline` 的 `bl.lock`，
> 要么开机时看 fastboot 界面的 "sec unlocked"。

## 三、全系统去广告（hosts）

### 最终效果

```
/system/etc/hosts   10607 行，6541 条拦截规则
analytics.163.com → 127.0.0.1    ✅ 已拦
crash.163.com     → 127.0.0.1    ✅ 已拦
www.baidu.com     → 157.148.69.151 ✅ 正常
```

开机自动挂载，**不依赖 AdAway 常驻，也不占用 VPN 通道**。

### 规则来源

AdAway 官方清单：`https://adaway.org/hosts.txt`（243 KB / 6542 条）

### 踩坑：overlayfs 不支持 F2FS 作为 upperdir

`systemless-hosts` 模块原本的 `service.sh`：

```sh
mount -t overlay -o lowerdir=/system/etc,upperdir=$MODDIR/system/etc,workdir=$MODDIR/worker KSU /system/etc
```

在这台机器上直接失败：

```
overlayfs: filesystem on '/data/adb/modules/systemless-hosts-KernelSU-module/system/etc' not supported
mount: 'KSU'->'/system/etc': Invalid argument
```

**原因**：内核的 overlayfs 不接受 F2FS（`/data`）作为 upperdir。

**解决**：改成 bind 挂载单个文件——

```sh
MODDIR="${0%/*}"
mount -o bind "$MODDIR/system/etc/hosts" /system/etc/hosts 2>/dev/null
```

原文件已备份为同目录的 `service.sh.orig`。

> ⚠️ **不要更新这个模块**，更新会覆盖 `service.sh`，广告拦截失效。
> 更新后重新改一遍即可。

### 手动验证

```powershell
adb shell su -c "wc -l /system/etc/hosts"                 # 应为 10607
adb shell su -c "mount | grep hosts"                      # 应有 1 条 bind 挂载
adb shell "ping -c 1 analytics.163.com"                   # 应解析到 127.0.0.1
```

### 更换规则

```powershell
adb push 新的hosts.txt /sdcard/Download/hosts.txt
adb shell su -c "cp /sdcard/Download/hosts.txt /data/adb/modules/systemless-hosts-KernelSU-module/system/etc/hosts"
adb shell su -c "chmod 644 /data/adb/modules/systemless-hosts-KernelSU-module/system/etc/hosts"
adb shell su -c "mount -o bind /data/adb/modules/systemless-hosts-KernelSU-module/system/etc/hosts /system/etc/hosts"
```

## 五、Play 商店的处理

原厂 `/product/priv-app/Phonesky_CN/Phonesky_CN.apk` 版本 22.7.53，
**没有任何可启动的 Activity**（`cmd package resolve-activity` 返回 `No activity found`）。

处理方式：直接从 APKPure 下载通用版 APK 覆盖安装。

```
旧：22.7.53   → 新：52.9.21-24
签名校验通过（同为 Google 签名），无需卸载原版
启动项：com.android.vending/.AssetBrowserActivity
```

APK 保留在 `_apps\PlayStore-universal.apk`（101 MB），系统更新把它还原时重装即可。

> 注意：APKPure 走代理时证书校验会失败，下载需要跳过 SSL 验证
> （`ssl._create_unverified_context()`），装前可用 `adb install` 的签名校验兜底。
