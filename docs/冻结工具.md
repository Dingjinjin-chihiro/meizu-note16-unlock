# 魅族专用冻结工具

> 日期：2026-11-01
> 设备：MEIZU Note 16（M521Q / UMS9621S）· Flyme 12.0.1.7A · KernelSU root
> 目的：**只冻结、不卸载**，通过导入包名列表批量管理自带应用

---

## 一、为什么自己写

### 小黑屋（`web1n.stopapp`）是闭源的

查了作者 GitHub（`web1n`，142 个公开仓库），与小黑屋相关的只有两个：

| 仓库 | 内容 |
|---|---|
| `blackhouse-app-setup-command` | **一键激活脚本**（Shell），不是 App 源码 |
| `Ice-Box-Docs` | **在线文档**，不是源码 |

**没有任何一个仓库是 `web1n.stopapp` 的源码。** 所以想要「导入列表批量冻结」这个能力，
自己写一个反而更快、更可控——它底层就是 `pm disable-user`，没有黑盒。

### 黑阈 ≠ 小黑屋

| | 机制 | 效果 |
|---|---|---|
| **黑阈**（`me.piebridge.brevent`） | 待机（standby） | 应用保持安装，只是不进后台 |
| **小黑屋**（`web1n.stopapp`） | 冻结（`pm disable`） | 应用彻底不可启动，等同禁用 |
| **本工具** | 同小黑屋 | 同小黑屋，但可批量导入列表 |

## 二、两个版本

| 文件 | 运行位置 | 适用场景 |
|---|---|---|
| `scripts/meizu-freeze.ps1` | 电脑（adb） | 批量操作、生成日志与回滚脚本 |
| `scripts/meizu-freeze.sh` | 手机（root/Termux） | 不接电脑时使用 |

### 共同特性

- **只冻结不卸载**，随时 `unfreeze` 还原
- **内置保护名单**：桌面、系统界面、设置、电话、短信、输入法、WebView、蓝牙、NFC、
  网络栈、KernelSU 管理器、小黑屋本身 —— 即使列表里写了也不会冻结
- 资源类（`*.overlay`、`com.android.wifi.*`、`com.unisoc.*` 等）自动跳过
- 支持备注：每行 `包名 空格 备注`，或 `#` 注释

## 三、PC 版用法

```powershell
# 预演（不实际修改）
.\meizu-freeze.ps1 -Action freeze -List meizu-freeze-list.txt -DryRun

# 冻结
.\meizu-freeze.ps1 -Action freeze -List meizu-freeze-list.txt

# 解冻
.\meizu-freeze.ps1 -Action unfreeze -List meizu-freeze-list.txt

# 查看状态
.\meizu-freeze.ps1 -Action status -List meizu-freeze-list.txt

# 导出设备上当前所有冻结项
.\meizu-freeze.ps1 -Action export -List current-frozen.txt

# 只处理魅族自家应用
.\meizu-freeze.ps1 -Action freeze -List all.txt -OnlyMeizu
```

每次 freeze 都会生成：

```
_freeze_logs/freeze_20261101_163102.txt              # 本次冻结清单
_freeze_logs/freeze_20261101_163102._unfreeze.ps1    # 一键回滚脚本
```

## 四、手机端用法

```sh
# 推到手机
adb push meizu-freeze.sh /sdcard/freeze/meizu-freeze.sh
adb push meizu-freeze-list.txt /sdcard/freeze/list.txt

# 冻结
adb shell su -c "sh /sdcard/freeze/meizu-freeze.sh freeze /sdcard/freeze/list.txt"

# 解冻
adb shell su -c "sh /sdcard/freeze/meizu-freeze.sh unfreeze /sdcard/freeze/list.txt"

# 查看状态
adb shell su -c "sh /sdcard/freeze/meizu-freeze.sh status /sdcard/freeze/list.txt"

# 导出
adb shell su -c "sh /sdcard/freeze/meizu-freeze.sh export /sdcard/freeze/frozen.txt"
```

Termux 里同理（先用 `su` 提权）。

## 五、清单文件格式

```
# 注释行
com.meizu.flyme.weather      天气
com.meizu.media.music        音乐
com.android.browser          浏览器

# 也可以只写包名
com.meizu.mstore
```

`scripts/meizu-freeze-list.txt` 是**实机导出的 124 个冻结项**，可直接当模板改。

## 六、实测记录

| 测试 | 结果 |
|---|---|
| `status` 识别 已冻结/启用中/未安装 | ✅ |
| `freeze` 跳过保护名单（`com.android.settings`） | ✅ |
| `freeze` 跳过不存在的包 | ✅ |
| `freeze` 真实冻结相机 → `status` 显示已冻结 | ✅ |
| `unfreeze` 恢复 → `status` 显示启用中 | ✅ |
| `export` 导出 124 个冻结项 | ✅ |
| 设备端脚本 freeze / unfreeze / status / export | ✅ |

### 踩过的 bug（已修）

第一版 `meizu-freeze.sh` 用了 `for p in $PROTECT` 作为函数内的循环变量，
**shell 函数共享变量作用域**，把外层主循环的 `p` 覆盖了，结果冻结了保护名单里的最后一个包
（`web1n.stopapp`，也就是小黑屋自己）。

修复：函数内改用 `_pp`。教训：**在 sh 里，函数和主流程不要用同名循环变量。**

## 七、注意

- 冻结前建议先 `-Action export` 存一份当前状态
- 冻结系统组件后如果出现异常（多半是桌面/通知相关），`unfreeze` 立刻恢复
- **不要冻结**：`com.meizu.flyme.launcher`、`com.android.systemui`、`com.android.settings`、
  电话短信相关、输入法、WebView —— 保护名单已覆盖，除非用 `-Force`
- 冻结不等于删除；APK 始终在 `/system` 或 `/product` 里，解冻即可恢复
